# Episode 3 — verification log

| Claim | Primary source | Corroborating source |
|---|---|---|
| Home routers commonly perform NAT, presenting one public IP for multiple devices | Well-established, textbook networking behavior; consistent with [RFC 6598](https://datatracker.ietf.org/doc/html/rfc6598)'s own description of the broader NAT context it addresses | — |
| Carrier-grade NAT (CGNAT) shares one public IPv4 address across hundreds to thousands of subscribers using distinct port ranges, common on mobile carrier networks | [RFC 6598, IANA-Reserved IPv4 Prefix for Shared Address Space](https://datatracker.ietf.org/doc/html/rfc6598) (IETF, primary — defines the 100.64.0.0/10 block for exactly this use, and its restrictions: must not appear in public DNS, must not be forwarded by backbone routers) | [SANS Internet Storm Center — "RFC 6598 - Carrier Grade NAT"](https://isc.sans.edu/diary/20777) |
| `X-Forwarded-For` is a de facto convention, not part of core HTTP, with vendor-specific variation | Consistent with RFC 7239's own stated purpose (see below) | [DevCentral/F5 — "Forwarded HTTP Extension Insertion (RFC 7239)"](https://community.f5.com/kb/codeshare/forwarded-http-extension-insertion-rfc-7239/287787) |
| RFC 7239 defines a standardized `Forwarded` header intended to replace `X-Forwarded-For`/`-Proto`/`-Host`, published June 2014, with syntax for `for=`/`proto=`/`by=` parameters and guidance for anonymizing the client address | [RFC 7239, Forwarded HTTP Extension](https://www.rfc-editor.org/rfc/rfc7239.html) (IETF, primary) | [datatracker.ietf.org/doc/html/rfc7239](https://datatracker.ietf.org/doc/html/rfc7239) — same document, independent index entry confirming publication date/status |
| Forwarded-for style headers are client-suppliable and must not be trusted as authoritative unless the sending proxy is explicitly known/configured | This project's own `src/server/collectors/network.ts` implements exactly this trust model (TCP-observed IP trusted; `X-Forwarded-For`/`Forwarded`/`X-Real-IP` reported but marked `untrusted_client_suppliable`) — an internal, already-reviewed engineering decision, not an external claim requiring a citation | — |
| Geolocation/ASN lookup requires a separate database/service and is not automatic from an IP address alone | Consistent with how IP geolocation services are generally described (a lookup against a maintained database of address-range-to-location mappings, e.g. MaxMind GeoIP or similar); this project itself reports `network.asn`/`network.geo` as `not_configured` rather than performing such a lookup (see `src/server/collectors/network.ts`) | — |
